# 0010. 首頁點一列進格子頁，今天頁維持在圖示後面

- 狀態：已採納
- 日期：2026-08-23

## 決策

一份計劃表有三頁，動線維持現在這樣：

```
/dashboard           計劃表清單（原本在 `/`，見 [0014](0014-publish-oauth-app.md)）
  └ 點一列 ──────→  /plans/[id]          9×9 格子（規劃用的地圖）
                       ├ 右上圖示 ────→  /plans/[id]/today    今天
                       └ 右上圖示 ────→  /plans/[id]/review   回顧
```

不改成「首頁那一列直接通到今天頁」。

## 為什麼記下來

因為它看起來明顯是錯的，而且會一再被重新提起：使用頻率跟入口深度剛好相反。
今天頁一天開一次、格子頁想到新東西才開、回顧頁一個月一次——最常用的那一頁
反而要點兩下，第二下還是一個沒有文字的圖示。

真正該問的不是「哪一頁最常開」，而是**「打開這份計劃表」這個動作應該是什麼意思**。
現在的答案是「看我的地圖」。換成今天頁，答案就變成「看我今天要做什麼」，
這份 app 也就從長期目標管理往每日待辦清單挪了一步。
`CLAUDE.md` 寫的是「使用者會反覆回來看自己的表，所以回顧體驗就是產品本身」——
先讓地圖當大門，跟這句一致。

## 什麼時候該推翻

真的開始每天用之後。到那時判準是行為而不是推測：如果進了格子頁只是為了按右上角
那顆圖示，那大門就開錯地方了。屆時開新的決策編號取代這一篇，
不要直接改這裡。

## 後果

- 今天頁要能被單獨收藏——網址得是穩定的 `/plans/[id]/today`，不能塞進 query 或
  純前端狀態。目前就是。
- 格子頁右上那兩顆圖示是今天頁與回顧頁的唯一入口，不能為了清爽把它們藏起來。
