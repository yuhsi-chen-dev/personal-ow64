# 0007. 視覺語言：token 化的淺／深色、每個次目標一個色相

- 狀態：已採納
- 日期：2026-08-22

## 決策

風格取向是克制的現代感（Apple 那一路）：中性介面、大標題配負字距、
圓角卡片、柔和陰影、細微的 hover 位移。顏色不靠裝飾堆出來，而是來自資料本身。

### 顏色只有一個來源

8 個次目標各自有一個色相（`lib/palette.ts` 的 `HUES`，OKLCH 上大致等距）。
格子的底色 = 該區塊的色相依進度混進 surface。所以整張表的顏色就是進度本身，
沒有另外一套裝飾用色票。核心目標不屬於任何次目標，用中性的 `--accent`。

用 OKLCH 是為了 8 個顏色**視覺亮度一致**，不會有某一塊特別跳或特別糊；
換成 HSL 會做不到這件事。

### 空格子 vs 進度 0%

- 空格子（還沒想到要做什麼）：色相 **7%**，看得出屬於哪一區塊但明顯是空的。
- 有填但 0%（想到了都沒做）：`heat()` 的下限 **18%**。

這兩個必須拉開距離。`lib/board.test.ts` 有測試釘住，改動色階時不要讓它們靠近。

### 3×3 的結構靠留白，不靠邊框

版面是「9 個區塊的 3×3」，不是平的 9×9——區塊之間的縫（gap-2）比格子之間（gap-1）大。
這是曼陀羅表唯一不能妥協的視覺，9×9 看不出 9 個區塊的話，這張表就只是 81 個格子。

### 焦點放大：點哪塊哪塊就長大

81 格同時塞進一個畫面，每格就是 70px，字只能 8px——這是算術，不是設定問題。
要讓字可讀，**必須放棄「81 格同時都要能讀」這個前提**。

紙本的曼陀羅表也不是這樣用的：先看整張確定方位，再盯著其中一個 3×3 做事。
所以外層 3×3 的 `grid-template-columns/rows` 依照聚焦的區塊加權（2.2fr 對 1fr），
選中的那塊放大到約兩倍、字放大到 14px，其餘縮小成純色小地圖（不放字——
6px 的字誰也讀不了，留著只是雜訊）。fr 之間可以平滑補間，展開本身就是動態。

兩個實作上的坑：

1. **外層必須是固定的正方形**（`aspect-square`）。容器高度若是自動的，`fr` 不會照比例
   分配，聚焦的那一欄會把整張表撐得又高又歪。格子改用 `h-full` 而不是 `aspect-square`。
2. **互動是兩段式**：點到別的區塊只切換焦點、不開面板；點已聚焦區塊裡的格子才選取。
   一步到位的話，手機上剛長大的區塊會立刻被底部面板蓋住。

代價是未聚焦的區塊會被拉成長方形（魚眼變形）。倍率壓在 2.2 是變形與可讀性的折衷；
試過把未聚焦的格子畫成置中小方塊來掩飾變形，結果更糊，放棄了。

### 打卡是主要動作，該拿到最大的目標

打卡每天做好幾次，編輯偶爾才做一次。所以**聚焦後每格底部是一整條打卡按鈕**（圖示＋文字），
格子本體則留給「點開編輯」。

第一版是右下角一顆 16px 的圓圈，三個問題：目標太小又要跟「點格子開面板」搶同一格；
它同時是狀態又是按鈕，看不出「已完成」跟「可以按」的差別；沒有標籤所以沒人知道它幹嘛。
未聚焦時每格都掛一顆，整張表還很吵。

現在**未聚焦時完全不放按鈕**（純資訊），只有聚焦的區塊能打卡。這跟「先聚焦再動手」的
互動模型一致，也讓總覽乾淨。

按鈕的文字跟著型態與頻率走：習慣是「打卡」／「今天‧本週‧本月已完成」，
累計是「＋1」，里程碑是「標記完成」／「已完成」。已完成時整條填滿該區塊的顏色並停用——
留著可按但按了沒反應，比停用更讓人困惑。

**樂觀回饋**：按下去立刻變成完成的樣子，不等伺服器回來（`ActionForm` 的 children
可以傳函式拿到 `pending`）。少了這個，每次打卡都要等一次往返才有反應，感覺很鈍。

## 淺色／深色

所有顏色都是 `:root` 上的 CSS 變數，深色只覆寫同一組變數。
熱力圖用 `color-mix` 混 `--surface`，所以換主題時色階自己跟著走，不用維護兩套色票。

三種狀態：使用者明確選過會在 `<html>` 留 `data-theme`，沒選過就跟隨系統
（`@media (prefers-color-scheme: dark)` 但排除 `[data-theme="light"]`）。
`app/layout.tsx` 有一段同步的 inline script 在首次繪製前套用主題，
**不要把它搬進 React 元件**，否則深色使用者會先看到一閃的白畫面。

## 圖示：lucide-react

需要一整套風格一致、可上色、可 tree-shake 的圖示。自己畫 SVG 在數量上不划算，
emoji 在不同平台長得不一樣、也撐不起這個風格。

## 後果

- 新增顏色前先問「這個顏色代表什麼資料」。答不出來就不要加。
- `body` 是 flex column，所有 `<main>` 都要帶 `w-full`，
  否則會縮成內容寬度（這個 bug 讓格子一度只有 43px）。
- 深色模式下 `--accent` 換成更亮的綠，因為深底上的 emerald 對比不足。
