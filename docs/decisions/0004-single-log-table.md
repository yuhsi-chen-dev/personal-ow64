# 0004. 只用一張紀錄表

- 狀態：已採納
- 日期：2026-08-21

## 決策

`logs(actionId, day, occurredAt, value)`，[0003](0003-hybrid-tracking.md)
的三種型態共用這一張表。

- `daily`：一天一筆 `value = 1`，同日重複寫入視為冪等，**不要累加**。
- `count`：每次執行一筆 `value = n`。
- `percent`：每次更新一筆 `value = 0..100`，讀取取最新一筆，舊紀錄保留當趨勢。

不要為三種型態各開一張表。

## 理由

追蹤資料是時間序列，歷史紀錄必須保留，不能只存目前狀態，
否則熱力圖／趨勢圖之類的回顧視覺化做不出來。

`day` 與 `occurredAt` 兩欄都要留：`occurredAt` 是時間點，
換算成「使用者當地的哪一天」需要時區資訊，無法從 `occurredAt` 推導。

## 後果

ponytail: 同日冪等目前預計在寫入路徑用程式碼保證，沒有下 DB 唯一索引
（唯一索引只對 `daily` 正確，但索引不能只套一種型態）。單人 app 沒有並行寫入，
真的出現並行寫入時再改成 partial unique index。
