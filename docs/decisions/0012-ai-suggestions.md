# 0012. AI 建議：分兩步、只填空位、用 Gemini 免費額度

- 狀態：已採納
- 日期：2026-08-23

## 決策

使用者輸入核心目標之後，可以請 AI 幫忙拆。**分兩步，不是一次生 64 格**：

1. 先生 8 個次目標，使用者看過、採用、再自己改。（本篇實作的部分）
2. 之後才逐塊生它底下的 8 項行為。（還沒做）

模型走 **Google Gemini 的免費額度**，型號 `gemini-flash-lite-latest`。

## 為什麼分兩步

一次吐 64 格會拿到 64 個「還可以但都要改」的格子，那不是幫忙，是把發想的苦差事
換成校對的苦差事。而且次目標是高槓桿的決定——行為是從它推出來的，
使用者改了次目標之後，底下的行為本來就該照改過的版本重生。

`CLAUDE.md` 寫「使用者不會一次想出 64 項」。這個功能補的是那個洞，不是加一個花招。

## 不覆蓋，而且檢查兩次

`CLAUDE.md` 的第一優先序是歷史不能遺失或被覆蓋。次目標的 upsert 是照 position 寫的，
所以一則寫到已有內容位置的建議，會連同底下 8 項行為與所有打卡紀錄一起失去意義。

檢查在兩個時間點，缺一不可：

1. **產生建議時**（`lib/suggest.ts` 的 `assignToFreeSlots`）——建議只落在空位上，多的丟掉。
2. **按下採用時**（`app/actions.ts` 的 `acceptSubGoals`）——**重新查一次現在哪些位置是空的**。
   使用者可能在看建議的時候自己先填了某一格；相信產生當時的快照就會蓋掉他剛打的字。
   已經有人的位置直接跳過，不報錯——他要的東西已經在那裡了。

採用走的是跟手動存檔同一支 `upsertSubGoal` 與同一份 Zod schema。
**建議不該有繞過驗證與擁有權檢查的捷徑。**

## 模型的輸出是跨信任邊界的輸入

照 `decisions/0006`，一律 Zod。這裡有兩份 schema，回答的是不同問題：

- `subGoalResponseSchema`（手寫的 JSON Schema）是**給模型的提示**。手寫是因為
  Gemini 只吃 JSON Schema 的一個子集，字數限制的 `minLength`／`maxLength` 不在支援清單上，
  把 `z.toJSONSchema()` 的產物整包丟過去是在賭。
- `subGoalSuggestions`（Zod）是**關卡**。模型有權無視上面那份提示，Zod 這關過不了就是不收。

## 用免費額度的代價

**免費層通常代表送進去的內容可能被用於改進模型。** 這個 app 是多租戶的
（`decisions/0011`），送進去的是別人的人生目標。這是刻意接受的取捨，不是疏忽：
現階段是給認識的人用的側專案，省下的錢比隱私風險更具體。

但因此有兩件事必須成立：

1. **按鈕旁邊要寫明會把目標送到 Google 的 AI 服務。** 已實作。
2. **開放註冊之前，隱私政策要講清楚這件事。** 還沒做，跟 `decisions/0011` 列的
   刪帳號路徑是同一批未竟事項。

哪天覺得這個代價不划算，換 provider 只要改 `app/ai-actions.ts` 一個檔——
`lib/suggest.ts`（提示詞、schema、不覆蓋的邏輯）完全不知道模型是誰。

## 還沒做的：限流

沒有任何限流。現在可接受，因為 Google OAuth 還在「測試中」——只有你手動加進清單的人
登得進來（`docs/deploy.md`）。**開放註冊之前一定要補**，否則任何註冊的人都能把你的
免費額度打光，或在你改用付費 API 之後直接花你的錢。

## 型號是量出來的，不是挑的

2026-08-23 用同一個提示詞實測：

| 型號 | 結果 | 延遲 |
|---|---|---|
| **`gemini-flash-lite-latest`** | ✓ 8 個 | **2.5s** |
| `gemini-3.5-flash` | ✓ 8 個 | 10.3s |
| `gemini-3.6-flash` | ✓ 8 個 | 18.7s |
| `gemini-flash-latest` | ✗ 503 | — |
| `gemini-3.7-flash` | ✗ 503 | — |
| `gemini-pro-latest` | ✗ 429 | — |

三個成功的品質差不多，都給出四個技能面向加上心態／環境／體能這類容易被忽略的維度。
既然如此就選最快的：**18 秒那個在 Vercel 上是地雷**，2.5 秒則讓執行時間上限
幾乎不再是問題。

**一定要用別名，不要用版號。** 同一次實測裡 `gemini-2.5-flash` 與 `gemini-2.0-flash`
都已經回 404「no longer available」——版號會被下架，別名跟著 Google 走。
（附帶一提，`models.list()` 列得出來的東西不一定叫得動，`gemini-2.5-flash` 就在清單上。）

## 503 是免費層的常態，重試一次

免費層拿的是剩餘算力，尖峰時會回 503「high demand」。上面那張表六個型號就有兩個中。
所以 503 重試一次——lite 只要 2.5 秒，重試的代價比讓使用者看到錯誤小得多。
**只重試 503**：金鑰無效或額度用完重試也不會變好，直接往上丟。

## 後果

- 多一組環境變數 `GEMINI_API_KEY`。
- 錯誤要在伺服器端留原文（`console.error`）。使用者只看得到一句翻譯過的話，
  但吞掉的錯誤等於沒發生過——第一次除錯時就是因為沒有這行，完全查不出 503。
- 型號被下架時 Google 回 404，`explain()` 會把型號名稱講出來，
  不然錯誤訊息看起來會像使用者做錯了什麼。
- 生成約 2–3 秒。本機沒問題，Vercel 的 function 有執行時間上限，**只會在部署後才炸**。
  真的撞到的話順序是先調 `maxDuration`、再改串流，最後才談背景工作——
  使用者就坐在那裡等結果，做成 queue 只是讓他一樣等，然後你多維護一整套狀態機。
