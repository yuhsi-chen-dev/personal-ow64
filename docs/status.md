## 已完成

- Next.js 16 + TypeScript + Tailwind 骨架（`create-next-app`）。
- 領域核心（純函式，不碰 React 也不碰資料庫）：`lib/mandala.ts` 9×9 座標映射、
  `lib/progress.ts` 四型態進度彙總、`lib/day.ts` 當地日期與週期、
  `lib/board.ts` 81 格顯示模型、`lib/palette.ts` 每個次目標的色相。
- 資料層：Neon Postgres，`db/schema.ts` 四張表 + 初始 migration，已套用到 Neon。
- 輸入驗證：`lib/schemas.ts`（Zod，照 decisions/0006 的規格）+ `lib/schemas.test.ts`。
- 追蹤方式四類（習慣＋頻率／累計／里程碑／信念），見 `decisions/0008`。
  舊的三類已用 migration 0001 搬過去，實際查資料庫確認過。
- 寫入路徑：`app/actions.ts` 四個 server action（建立計劃表、存次目標、存行為、打卡），
  搭配 `db/queries.ts` 的讀取。次目標與行為用 upsert（靠 (planId, position) 與
  (subGoalId, position) 的唯一索引）；同期冪等在 `db/writes.ts` 的 `logOnce` 裡先查再寫，
  範圍跟著 trackingType 走（習慣是當期、里程碑是永遠一次、累計不冪等）。
- 畫面（已重做）：`/` 是首頁與計劃表清單，`/plans/[id]` 是 9×9 熱力圖，
  點區塊放大（焦點＋小地圖）、點格子開右側面板編輯、聚焦後每格底部一條打卡按鈕（含樂觀回饋）。
  淺色／深色可切換並記住選擇。
  視覺語言見 `decisions/0007`。兩頁都是 `force-dynamic`。
- 整合測試：`db/write-path.test.ts` 對真實資料庫驗 upsert 與同日冪等。

## 已驗證到哪

寫入路徑已在真實資料庫上走過一遍（2026-08-22），以下都是查資料庫確認、不是看畫面：

- **結構**：4 張表與兩個唯一索引實際存在。
- **讀取**：`getDb()` 的 lazy 連線、`loadPlan()`、`rollup()` 對真實資料實跑成功，
  進度數字正確（當時是 1 筆每日打卡 ÷ 30 天 = 3%）。
- **寫入**：建立計劃表、存次目標、存行為、打卡，四件都寫得進去。
- **upsert**：同一格改標題再存，該列被更新而非新增，`onConflictDoUpdate` 確實命中唯一索引。
- **同期冪等**：同一天第二次打卡沒有新增紀錄，時間戳維持第一次的。
  改成四類之後，整合測試也涵蓋「累計型同一天可以記多次」的反向案例。

過程中抓到兩個 bug，都已修掉：非 count 型的行為被目標欄位擋下（錯誤訊息還漏出 Zod 原文），
以及打卡日期用 UTC 算導致跨時區記錯天。
